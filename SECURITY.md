# Security policy

## Supported version

Only the latest commit on `main` is maintained.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's private vulnerability reporting feature and include the affected route or component, reproduction steps, impact, and a proposed mitigation if available.

Do not test against infrastructure you do not own or lack explicit authorization to assess. Avoid denial-of-service testing and do not include live tokens, passwords, personal data, or AWS account identifiers in a report.

## Response targets

- Acknowledge a valid report within three business days.
- Triage severity and affected versions within seven business days.
- Publish a remediation timeline after impact is understood.

These are lab targets, not a commercial service-level agreement.
